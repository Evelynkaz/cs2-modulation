## Этап 1 — VPK, контейнер ресурсов, KV3 (завершён)

### Сделано

`s2fmt::vpk` — VPK v1/v2 (dir + нумерованные архивы), preload, CRC32,
позиционные потокобезопасные чтения, лояльные к именам пути, повтор с
ограниченным размером дерева при переполнении. `s2fmt::compress` — блочный
LZ4, цепочечный LZ4 со словарём, zstd через `ruzstd`, Valve BlockCompress;
ограничения на коэффициент сжатия. `s2fmt::kv3` — бинарный формат v0–v5 со
всеми видами сжатия, строгое исчерпание lane'ов, текстовый парсер/writer,
модель Value/Object, `binary_header_info`. `s2fmt::resource` — заголовок и
таблица блоков (включая блоки нулевого размера с raw- и
filtered-индексами), поиск встроенного PHYS, манифест vrman, тип ресурса по
расширению. CLI: `cs2mod vpk ls|cat|verify`, `cs2mod res [--vpk] [--block]
[--kv3]`, голые имена карт через `--game`/`CS2_GAME_DIR`, защита записи
(только `data/` и `cache/` внутри git-дерева).

### Проверено

118 unit-тестов `s2fmt` + 20 у cli; игнорируемые тесты на реальных данных:
`de_mirage.vpk` — 757 записей, CRC верны, все 696 `*_c` парсятся, 2 806
блоков KV3 (v5, LZ4/zstd), `world_physics.vmdl_c` PHYS: 1 part, 1933 hulls,
8 meshes, 9 collision attributes; `pak01_dir.vpk` — 135 686 записей / 494
архива, каждый блок KV3 каждого `*_c` (≈242 тыс. блоков) парсится (≈80–93 с
в release); все 272 фикстурных KV3-блока VRF и 42 текстовых файла;
пробы на враждебный ввод (allocation/recursion bombs) возвращают ошибки;
максимальная реальная глубина вложенности KV3 — 9 (mirage) / 32 (pak01)
против лимита 128. Ревью: 5 раундов, все замечания исправлены.

### Осталось

Понизить `MAX_DECOMPRESSED_SIZE` (1 ГиБ) до нескольких размеров самого
большого измеренного на pak01 буфера, либо ограничить суммарное число
значений на документ (zstd-бомба из плоских массивов Null всё ещё может
исчерпать память); raw- и filtered-индексы CTRL-блока не проверены на
реальном vmdl_c с пустым блоком перед PHYS; BlockCompress (v0 binary_bc) не
покрыт тестами на реальных файлах.

### Решения

CS2 build 2000908 в использовании; лимит рекурсии KV3 — 128 (в debug при
потолке стека 1 МиБ выдерживает ~176, реальный максимум — 32); байты после
KV3-документа разрешены (реальный файл `viewmodel_inspects.vnmgraph_c`
хранит документ дважды; VRF это не проверяет); строгое исчерпание по
lane'ам сохранено; текстовый KV3 не различает Int/UInt для неотрицательных
чисел — потребители используют `as_i64`/`as_u64`/`as_f64`; `kv3` остаётся
общим форматом, разбор blob-vs-array для физики — задача этапа 2;
тесты на реальных данных помечены `#[ignore]` и читают
`CS2_GAME_DIR`/`VRF_TEST_FILES`, файлы игры в репозиторий не копируются.
